# AI 可靠性、证据账本与商业化验收升级设计

## 1. 文档状态

- 状态：待产品确认
- 日期：2026-08-27
- 范围：升级项 3、4、5、6、7、8
- 前置基线：`2026-08-26-commercial-data-integrity-design.md`

本文只定义设计与验收口径，不代表功能已经实现或通过上线验收。产品确认后再拆分实施计划，并按测试驱动方式开发。

## 2. 目标

在现有真实行情、新闻、TOP50、12-Agent 和定时任务基础上，建立一套可以追溯、可以解释、可以降级、可以验收的研究系统：

1. AI 研究任务稳定执行，明确区分独立 Agent 结果与共享模型降级结果。
2. 预测准确率由冻结预测样本自动计算，不使用演示数字，不回改历史结论。
3. TOP50 每次选股保存完整证据，能够回答“为什么入选、何时失效、后来表现如何”。
4. 新闻按来源可信度、A 股相关性、时效和传导路径排序，降低误分类与信息噪声。
5. 运维页面能快速定位数据源、调度、AI 和通知故障，同时不暴露密钥及供应商原始错误。
6. 建立桌面、移动、键盘、压力、降级和交易时段连续运行的正式验收门槛。

## 3. 约束与非目标

- 本系统不增加登录系统；运维页面只展示脱敏、只读信息，管理操作继续由服务端管理令牌保护。
- 本地机器即当前正式运行环境，仍必须区分开发验证、验收通过和可用于实盘参考三种状态。
- 不新增行情供应商，不承诺秒级行情，不把集合竞价、日线或旧快照标记为实时行情。
- 不实现自动下单、券商账户连接、收益承诺或自动资金管理。
- 不用静态业务数字、随机数或旧样本填充真实页面。
- 共享模型降级结果不得计为 12 个独立 Agent 的共识。
- 本批次不重构无关页面、不清理历史死代码、不修改用户的无关工作区改动。

## 4. 总体架构

采用“不可变事件账本 + 可重建查询快照”的结构：

```text
行情 / 新闻 / 交易日历 / MiniMax
              │
              ▼
       采集与任务编排层
              │
              ├── AI 运行事件
              ├── TOP50 冻结预测
              ├── 预测到期评估
              ├── 新闻评分结果
              └── 运维状态事件
                       │
                       ▼
                 KV 事件账本
                       │
                       ▼
             面向页面的派生快照 API
```

原则：页面读取派生快照，审计读取原始事件；派生快照损坏时可以从事件账本重建。历史预测只能追加评估或更正事件，不能覆盖原始预测。

### 4.1 存储键

| 键 | 用途 | 保留期 |
|---|---|---:|
| `ai-run:<jobId>` | 单次研究任务、12 个 Agent 尝试及降级记录 | 90 天 |
| `prediction:<predictionId>` | 单只股票、单周期的冻结预测 | 至少 3 年 |
| `prediction-events:<predictionId>` | 到期评估、更正、失效事件 | 至少 3 年 |
| `top50:snapshot:<snapshotId>` | 一次四周期排名和证据清单 | 至少 3 年 |
| `accuracy:latest` | 从已到期预测派生的准确率快照 | 可重建 |
| `news:scored:latest` | 已分类、评分、去重的最新资讯 | 7 天 |
| `ops-event:<eventId>` | 数据源、任务、通知和恢复事件 | 90 天 |
| `operations:latest` | 运维中心当前状态 | 可重建 |

## 5. AI 研究室可靠性

### 5.1 执行模型

- 一个研究任务包含 1 至 12 个已选择老师 Agent。
- 同一设备同一任务最多同时执行 1 个 MiniMax 请求，避免并发造成限流和结果丢失。
- 单 Agent 连接超时 10 秒，总超时 70 秒；只对 `rate_limit`、`timeout`、`upstream` 做一次立即重试。
- 12-Agent 任务最长执行 15 分钟；超时后保留已完成结果，其余标记失败，不无限等待。
- 状态统一为 `queued`、`running`、`retrying`、`completed`、`failed`。

### 5.2 独立结果与降级结果

- 每个 Agent 的独立调用保存自己的模型、老师版本、耗时、状态和结构化结论。
- 只有独立调用成功的结果进入 `independentSuccessCount` 和 Agent 共识计算。
- 只有当全部独立调用失败时，才允许生成一次共享模型降级总结。
- 降级结果必须返回 `fallbackMode: "shared_model"`，页面展示“共享模型降级”，不得显示为“12-Agent 共识”。
- 如果至少一个独立 Agent 成功，页面展示部分成功，并列出失败人数与原因分类。

### 5.3 错误分类与指标

内部错误分类固定为：`auth`、`quota`、`rate_limit`、`timeout`、`upstream`、`empty_response`、`validation`。公开页面只显示脱敏说明。

运维指标包括：各 Agent 近 30 次成功率、P50/P95 耗时、重试率、共享模型降级率、队列深度、最长等待时间。不得记录 API Key、完整系统提示词或知识文档正文。

## 6. 预测准确率证据

### 6.1 冻结预测结构

每条预测至少包含：

- `predictionId`、`snapshotId`、股票代码、名称、行业、周期；
- `generatedAt`、`tradeDate`、`dataCutoff`、`maturityTradeDate`；
- 因子版本、老师知识版本、独立 Agent 投票和独立成功数；
- 上涨概率、预测方向、参考入选价；
- 触发条件、失效规则、失效价格；
- 市场状态、数据源血缘、证据完整度；
- `pending`、`evaluated`、`invalidated` 三种生命周期状态；
- 到期价、区间最高/最低价、方向是否命中、区间收益、最大不利波动、评估时间和评估数据源。

预测生成后不可编辑。纠错必须追加 `correction` 事件，并保留原值、改值、原因与时间。

### 6.2 计算口径

- 只统计已到期且完成评估的冻结预测。
- 方向命中率 = 方向判断正确的样本数 / 可评估样本数。
- 概率质量使用 Brier Score；同时展示平均区间收益和最大不利波动，不换算成实盘收益承诺。
- 分组维度为：周期、行业、市场状态、主要支持 Agent。
- 每个指标始终展示样本数 `n`；`n < 10` 时只显示“样本不足”，不显示百分比结论。
- 历史不完整样本标记 `evidenceCompleteness: "partial"`，不与完整新样本混算主要准确率。
- 页面披露统计截止时间、预测期限、样本排除规则和数据源。

### 6.3 页面与接口

`GET /api/accuracy` 返回总体指标、分层指标、最近完成评估记录、样本口径和更新时间。`GET /api/accuracy/evidence?predictionId=<id>` 返回单条冻结预测与评估链路。“查看验证详情”只进入准确率证据页，不再复用风险中心路由。

## 7. TOP50 冻结证据闭环

### 7.1 快照生成

每次四周期选股生成唯一 `snapshotId`。超短、短线、波段、中长线分别保存完整排名，不因页面只预览 TOP10 而丢弃其余样本。

每只入选股票保存：排名、综合分、因子分解、支持与反对 Agent、数据截止时间、行情来源、新闻证据、风险门槛、入选理由、触发条件、失效条件和对应 `predictionId`。

### 7.2 证据查看

- 首页四周期标签各展示最多 10 只真实股票；无数据时展示原因和最后成功时间，不只显示空表头。
- 点击股票打开单股浮层；点击“选股证据”进入该次快照对应的证据详情。
- `GET /api/top50/evidence?predictionId=<id>` 返回入选证据、冻结时间、数据血缘、后续评估和更正事件。
- 旧快照可以回放但不能重排；新因子版本只影响新快照。

## 8. 新闻影响与相关性引擎

### 8.1 确定性评分

新闻总分为 0—100，先由可审计规则计算：

| 分项 | 分值 |
|---|---:|
| 来源可信度 | 0—25 |
| 金融与 A 股相关性 | 0—25 |
| 时效性 | 0—20 |
| 股票/行业实体匹配 | 0—20 |
| 海外向 A 股传导路径 | 0—10 |

- `>= 70`：首页主要资讯与要闻滚动候选。
- `50—69`：资讯中心普通内容。
- `< 50`：全球观察或低优先级，不进入首页主要资讯。
- 娱乐、明星、综艺等明确非财经内容直接拒绝。

### 8.2 分类与解释

每条资讯返回 `marketScope`、`relatedStocks`、`relatedIndustries`、`score`、`scoreBreakdown`、`classificationReason`、`transmissionPath` 和原文链接。AI 可以补充摘要和传导解释，但不能覆盖确定性市场分类与来源事实。

新闻去重使用规范化标题、来源和时间窗口；同一事件保留可信度最高的主条目，其余作为关联来源。所有新闻点击直接打开原文，不在页面伪造全文。

## 9. 运维中心与告警

### 9.1 运维页面

新增只读、脱敏的 `GET /api/operations`，按行情源、新闻源、AI、定时任务、通知渠道五组返回：当前状态、最后成功时间、最后失败时间、连续失败次数、P95 耗时、快照年龄、队列深度和最近恢复事件。

状态分为：`healthy`、`degraded`、`critical`、`unknown`。前端必须同时展示数据观察时间；没有时间戳时不能显示“正常”。

### 9.2 告警规则

- 只在状态变化时通知：健康转降级、降级转严重、异常恢复。
- 同一组件、同一错误分类 60 分钟内只通知一次；重复次数在运维中心累计。
- 页面不展示供应商 URL、Token、原始响应体、调用栈或内部文件路径。
- 用户级风险提示与系统运维错误分离，接口错误不得进入股票风险结论。

## 10. API 契约变更

| 接口 | 变更 |
|---|---|
| `GET /api/ai/jobs/:id` | 增加逐 Agent 状态、错误分类、独立成功数、降级模式和耗时 |
| `GET /api/top50` | 增加 `snapshotId`、数据截止时间、证据完整度和空数据原因 |
| `GET /api/top50/evidence` | 新增单条选股冻结证据 |
| `GET /api/accuracy` | 增加分层指标、样本数、Brier Score、截止时间与口径 |
| `GET /api/accuracy/evidence` | 新增单条预测评估链路 |
| `GET /api/news` | 增加评分拆解、市场范围、实体、行业和传导路径 |
| `GET /api/operations` | 新增脱敏运行状态与告警摘要 |

所有接口保留当前可用字段，新增字段向后兼容。无法计算的字段返回 `null` 与明确原因，不填充默认业务数字。

## 11. 数据迁移

- 旧预测尝试从现有快照补齐可确定字段；不能确定的字段保持 `null`，标记为 `partial`，不得推断补造。
- 旧 TOP50 快照标记为旧版本，不回写新因子证据。
- 现有新闻在下次采集时重新评分；历史新闻不进行无限量批量回填。
- 现有原始告警不删除，运维页面只生成脱敏聚合视图。
- 发布前保存当前 KV 关键快照、构建产物和环境变量名称清单；备份不包含密钥明文。

## 12. 降级行为

- 行情失败：保留最后成功快照，显示来源、观察时间和过期状态，暂停依赖新行情的预测评估。
- 新闻失败：保留最后成功新闻并显示更新时间，不生成虚假新条目。
- 部分 Agent 失败：展示已完成独立结果和失败人数；全部失败时才允许共享模型降级。
- 评估数据不足：预测保持 `pending`，准确率分母不增加。
- 运维快照生成失败：页面显示 `unknown` 和最后成功时间，不显示绿色正常状态。

## 13. 实施阶段

1. **证据底座**：事件结构、冻结预测、迁移、准确率计算和接口测试。
2. **研究可靠性**：AI 队列、重试、错误分类、独立/降级展示和运维指标。
3. **信息质量**：TOP50 证据详情、新闻评分、去重、分类解释和页面联动。
4. **运营验收**：运维中心、告警状态机、浏览器矩阵、压测、长时运行和发布证据包。

每个阶段独立通过自动化与浏览器验收后再进入下一阶段，避免同时改动所有数据链路后无法定位回归。

## 14. 验收标准

### R3 AI 研究可靠性

- 测试覆盖成功、限流、超时、空响应、部分成功和全部失败六类情形。
- 全部独立调用失败时，页面明确显示共享模型降级；该结果不进入独立共识。
- 连续执行 10 次多 Agent 测试任务，无任务卡在 `running` 超过 15 分钟。

### R4 准确率真实计算

- 每个页面数字可以追溯到冻结预测和到期行情。
- 修改因子版本不会改写已有预测。
- `n < 10` 的分组不显示具有误导性的百分比结论。
- 手工抽取至少 10 条样本复算，与接口结果一致。

### R5 TOP50 证据闭环

- 四周期均能显示真实排名或清晰空数据原因。
- 任一展示股票都能打开对应冻结证据、失效规则和评估状态。
- 页面 TOP10 与对应完整快照的前 10 名一致。

### R6 新闻质量

- 固定测试集覆盖 A 股、美股、港股、宏观、行业、个股和娱乐噪声。
- “美股/全球”不得因普通 `ETF` 字样误收 A 股内容。
- 首页主要资讯全部满足评分阈值并可解释评分组成。
- 新闻点击直接打开有效原文链接。

### R7 运维与告警

- 人为模拟 429、504、AI 超时、新闻源失败和通知失败，状态与告警正确变化。
- 同类错误 60 分钟内只通知一次，恢复时产生一次恢复通知。
- 浏览器响应和页面中不存在密钥、完整供应商错误或内部调用栈。

### R8 正式验收

- 浏览器尺寸：1440×900、1024×768、509×865、390×844；主要页面无横向溢出或遮挡。
- 键盘：侧栏、四周期标签、搜索、股票浮层、AI 发送和证据页均可操作；焦点可见，`Escape` 关闭浮层并返回触发点。
- 公共缓存型 GET 接口以并发 20、累计 200 请求测试：0 个 5xx，P95 小于 500ms。
- 调度进行至少 8 小时连续 soak 测试，无重复执行、任务永久卡住或未去重告警。
- 至少跨越 2 个完整 A 股交易日观察行情、TOP50、新闻、预测评估和通知后，才能标记“可用于正式自测”。
- 自动扫描页面与接口，不存在静态业务数字、随机行情、伪造准确率或无时间戳的“实时”标签。

验收证据统一保存到 `audit-commercial-release-YYYY-MM-DD/`，包含截图、控制台结果、接口样本、测试日志、调度日志、版本号、数据截止时间和已知限制。

## 15. 风险与取舍

- 单并发 AI 执行会增加 12-Agent 总耗时，但比高并发触发限流更可控；页面以逐 Agent 进度降低等待不确定性。
- `n >= 10` 只能抑制最明显的小样本误导，不能证明策略可盈利；页面必须持续披露样本数和市场区间。
- 确定性新闻评分可审计，但规则需要随误分类样本迭代；禁止让模型直接改写来源和市场事实。
- 本地单机没有高可用能力；进程、网络或设备故障仍会中断服务。运维中心解决的是可见性，不等于容灾集群。

## 16. Definition of Done

只有同时满足以下条件，升级项 3—8 才能视为完成：

1. 所有新增与回归自动化测试通过，构建通过。
2. 浏览器完成桌面与移动端真实交互验收，不以接口成功替代页面验收。
3. 每个准确率、TOP50 和新闻结论均可追溯到真实数据与时间戳。
4. 共享模型降级、旧快照、过期行情和样本不足在页面中被明确标注。
5. 关键故障模拟、压力测试、8 小时 soak 和两个完整交易日观察均有证据。
6. 发布证据包记录版本、已知限制、回滚方法和未通过项；存在关键未通过项时不得宣称整站已可商业化上线。
