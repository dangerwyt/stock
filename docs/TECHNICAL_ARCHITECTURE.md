# 技术架构现状 · 2026-09-07

## 1. 实际运行链路

浏览器 React 页面 → 同源 `/api/*` → Worker 数据服务 → 共享快照存储 → 行情、新闻、AI 供应商。

- 本地：Vite API 插件调用同一 Worker；`.local-data/stock-state.json` 为持久化 KV，权限 0600，临时文件原子替换、并发批量合并、写入失败后队列恢复。它仍是单进程文件存储，不支持多个写进程。
- Sites：Worker 默认导出 fetch / scheduled；`DB` 为 D1，state_store 保存 JSON 值及到期时间。建表在每个绑定首次使用时执行并缓存，初始化失败可重试；数据库迁移随发布包交付。
- 调度：甲方本地 launchd 每分钟调用管理端点并记录本地/Sites 两套验收文件。不是独立云端 Cron。管理调用必须带 ADMIN_API_TOKEN。
- 前端快照：同 URL 合并并发请求，20 秒超时、响应序号防覆盖；隐藏页面停止定时轮询，重新可见刷新。

## 2. 数据与长任务

行情主源为 Tushare 兼容接口，ProMax 为可配置备用/批量接口。新闻主源为晴红，备用为 Tushare major_news；NewsAPI 可选。每源先校验可用金融内容，再决定合并或切换；连续失败退避至最多 60 分钟。保留真实旧快照和明确降级，不伪造实时。

TOP50 使用交易日加因子版本的进度键及运行租约。候选快照只生成一次，Sites 每轮最多写 100 份预测，中断后从 offset 继续；已冻结记录使用 insert-if-absent。最终发布前再次校验实际上海时间早于 09:15，禁止盘中补造盘前预测。冻结与生成时间分开保存。历史算法版本不重写。

AI 研究支持 1–12 位画像逐步会诊。客户端与调度器均可推进同一检查点，租约防止同一步并发执行。后台每轮轮转处理最多两项，无浏览器也可续跑；15 分钟截止仍有效。停止入口停止后续步骤，已进行的上游请求可能仍完成并产生费用。按匿名客户端和网络限流，并保留每部署每日调用次数上限。记录供应商实际 usage，价格未配置时 cost 为 null，不能宣称金额预算或本地/Sites 统一账单。

## 3. 预测证据

生成时保存股票、参考价、目标交易日、因子版本、数据来源和冻结基准。成熟后追加验证事件，不能重写原预测。整体及每组不足 30 条不显示命中率；配对基准不足 30 条不显示超额收益。方向评分不是概率，Brier 仅为未校准评分的探索性误差。周期与老师组样本重叠，30 条并不证明统计可靠。

## 4. 安全与自选

API 实际读取字节上限 64 KiB；意外异常返回公共错误码及追踪 ID，不返回原始上游详情。管理端点验令牌。公开阅读无需登录；匿名标识不是实名账户，不适合保存敏感资产或真实交易凭证。

自选默认当前浏览器，支持同源多标签同步、服务端同匿名标识恢复及代码导入导出。不同浏览器不能在无共同身份的前提下自动推断为同一用户，故未实现隐式合并。
